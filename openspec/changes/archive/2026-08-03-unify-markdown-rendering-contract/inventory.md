# Markdown rendering callsite inventory

Change: `unify-markdown-rendering-contract`  
Inventory baseline: 2026-08-03  
Status: **completed implementation; behavior evidence is recorded in [`verification.md`](verification.md)**

This inventory is the callsite and implementation ledger for this change. Paths and symbol names identify the code reviewed during implementation; line numbers are intentionally omitted because concurrent work can renumber files. Every row has an implementation owner and a focused behavior-test obligation. “Direct insertion” means the point at which parser output, adapter output, or source-derived markup can reach a DOM sink.

## Contract identifiers used by this inventory

- **Parser baseline:** vendored `commonmark@0.31.2` ESM (`commonmark.Parser` + AST renderer `HtmlRenderer({safe:false, softbreak:'\n'})` semantics), with exactly GFM 0.29 tables, task list items, strikethrough and autolink literals implemented in the canonical AST layer. No `window.commonmark`, `window.marked`, `window.DOMPurify`, page-level parser state or surface options are permitted.
- **Declared GFM:** GFM 0.29 tables, task list items, strikethrough, and autolink literals only. The CommonMark 0.31.2 corpus is the conformance gate; the corpus is the parser-layer proof, not a sanitizer assertion.
- **Sanitizer:** vendored `DOMPurify@3.4.12` ESM, configured explicitly inside the adapter with the Safe Display Profile. The adapter's custom AST renderer escapes every source `html_block`/`html_inline` node before sanitization.
- **Adapter:** `window.TCRTMarkdown.render(source, { surface }) -> { html, status: 'ok'|'fallback', reason? }`; `html` is the only value a surface may display. `window.TCRTMarkdown.ready` always resolves to `{status:'ok'}` or `{status:'fallback', reason}` and never rejects. A fallback render is retried from the unchanged source only after a successful `{status:'ok'}` readiness result.
- **Source of truth:** source Markdown remains in the API/database/editor. A `data-markdown-source` or `data-original-markdown` DOM value is transient render state, not a replacement for persisted source. Sanitized/rendered HTML is never submitted as Markdown.

## Input provenance and trust rule

| Provenance ID | Origin | Examples in this repository | Trust classification | Required handling |
|---|---|---|---|---|
| P1 | User-authored editor text | Test Case Management fields, Test Run comments, QA AI Helper ticket editor | Untrusted | Preserve source; render only through the adapter; never interpolate source into HTML. |
| P2 | Database/API content | Test Case fields, Test Run fields/comments, QA ticket snapshots, Assistant history | Untrusted | Treat exactly like P1; re-render from source on every display. |
| P3 | AI-generated content | AI-assisted Test Case fields, Assistant replies, QA AI results | Untrusted | Treat exactly like P1; streaming and retries use the same adapter. |
| P4 | External Jira/Wiki content | Jira description/comments and ticket snapshot reloads | Untrusted | Backend conversion may produce source Markdown only; browser preview uses the adapter. |
| P5 | Application-generated syntax | Toolbar snippets, task markers, headings, links | Not a trust exemption | Renderer still sanitizes; task checkbox provenance must be GFM AST task metadata, never a source HTML element. |
| P6 | Backend source-only conversion | `_jira_wiki_to_markdown`, `_markdown_to_jira_wiki`, `_build_ticket_markdown`, outbound Jira issue description | Not browser display | Keep separate from browser parser/sanitizer; no HTML output or DOM insertion. |

### Checked but not Markdown renderer callsites

The repository has many `innerHTML`/`insertAdjacentHTML` uses for ordinary escaped labels, modals, tables, and i18n. They are not Markdown callsites unless a Markdown source value reaches the sink. The inventory must be extended if a future caller introduces such a value. In particular, Jira key/status tooltips (`M19`) and outbound Jira descriptions (`M18`) are intentionally separate from browser Markdown display.

## Migration order and deletion gate

1. **Freeze inventory and contract:** keep the corpus fixtures, GFM feature matrix, URL test vectors, result/reason contract, provenance policy, and focused test harness reviewable before treating any surface migration as acceptance-complete.
2. **Adapter and local assets:** vendor the pinned ESM modules, record integrity/hash/license metadata, implement `/static/js/common/markdown-renderer.js`, and load it before `assistant-widget.js` and every dependent page script. Prove `ready` and fail-closed output offline.
3. **Test Case Management (M03–M07):** migrate editor preview and AI/bulk paths together, including toolbar/hotkeys, then run its focused behavior tests.
4. **Test Run Execution (M08–M12):** migrate fields and comments, including edit round trips and readiness retries, then run focused behavior tests.
5. **QA AI Helper and Jira preview (M13–M17):** keep backend conversion source-only, migrate ticket display/editor, and test fetch/reparse/reload boundaries.
6. **Global Assistant Widget (M01–M02):** migrate initial, streaming, history, retry, table, and code presentation paths; remove lazy CDN loading.
7. **Legacy deletion:** only after every M01–M20 surface test passes, delete parser globals, page `setOptions`, regex renderer, local sanitizer, and CDN tags. Do not leave aliases or partial fallbacks.
8. **Governance closeout:** locale, accessibility, focused command-matrix, and browser evidence are complete; archive this change after syncing its verified contract into the main spec.
