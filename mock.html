按鈕系統 (Button)

SPEC-BTN-001
規則
  • Class 順序固定：btn btn-{variant} btn-sm（variant 在前、size 在後）
  • 圖示在文字左側，用 me-1 間距：<i class="fas fa-plus me-1"></i> 新增
  • 語意對應：btn-primary=新增/儲存 · btn-secondary=取消/返回 · btn-success=確認/套用 · btn-danger=刪除 · btn-info=特殊功能 · btn-warning=警告操作
  • 禁止使用：btn-xs、btn-view、btn-edit（非標準 class，僅單頁使用）
  • 禁止用 inline style 覆蓋 button 樣式（style="border:none;background:none"）
  • 所有頁面工具列按鈕統一用 btn-sm；modal 內可用標準 btn（不加 sm）

入口結構整合（唯一需要重構的部分）

SPEC-NAV-001
原則：維持頁面設計不變，只整合不合理的入口散落問題
問題 1：team_management 的 data menu dropdown（散落入口）
現況： team_management.html L24 的 btn-info dropdown 放了 audit-logs / team-statistics / system-logs 的連結 → 這三個管理功能不應藏在團隊管理頁的工具列 dropdown
修正： 移除此 dropdown，audit-logs / team-statistics / system-logs 改由 header 的「管理」dropdown 統一入口（見下圖）
問題 2：全域管理頁面的入口散落在 3 處
現況： team-management 在 index 頁 / org-management 在 team_management 按鈕 / audit-logs 在 data menu dropdown / system-logs 在 data menu / profile 在 user_menu
修正： header 新增「管理」dropdown（如下），統一入口。不新增頁面，不改現有頁面設計：
  • 組織
  • 團隊管理
  • 組織設定
  • 系統
  • 稽核日誌
  • 系統日誌
  • 統計分析
問題 3：automation provider/webhook 設定頁是獨立路由但只是 hub 的子管理面
現況： /automation-provider-settings 和 /automation-webhook-config 是獨立頁面，各有一個「Back to Hub」按鈕。三個頁面共用 automation-hub.css，內容高度相關。
修正方案 A（推薦）： 維持三個獨立路由不變，但 provider-settings 和 webhook-config 的 header 改為「< Automation Hub」breadcrumb 連結 + 統一的 toolbar，移除各自不同的 page_specific_actions 按鈕排列。
修正方案 B（如要更激進）： 將 provider/webhook 設定改為 hub 頁面 Settings tab 內的子面板（modal 或 drawer），消除兩個獨立路由。但這涉及較大 JS 重構。
問題 4：每頁都有 Home 按鈕佔工具列空間
現況： 全站 15 個頁面都有 btn-secondary btn-sm 的「回到首頁」/「首頁」/「Home」按鈕，佔工具列最右側。
修正（可選）： header 的 TCRT logo 設為首頁連結（慣例），移除各頁的 Home 按鈕 → 工具列少一個按鈕，更清爽。如保留則需先統一文案/class（見 SPEC-HOM-001）。
總結：以上 4 項是唯一需要「結構性」調整的入口問題。其餘頁面設計、layout、功能流不變，只需按照各元件 SPEC 修正 class/文案差異。
